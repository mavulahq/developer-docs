Legacy batch interoperability

Generate regulatory fixed-width exports and validate inbound legacy files through durable, tenant-scoped Workbench receipts.

Financial boundary: imports are staged and validated only. They never post ledger entries, execute lending operations or publish financial domain events.

Access and request controls

All operations require a bearer access token with compliance.manage. Write operations also require Idempotency-Key and X-Correlation-ID.

Request a regulatory export

curl -X POST "$WORKBENCH_URL/api/regulatory-exports" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Idempotency-Key: export-2026-07" \
  -H "X-Correlation-ID: compliance-run-2026-07" \
  -H "Content-Type: application/json" \
  -d '{
    "period_from":"2026-07-01",
    "period_to":"2026-07-31",
    "legal_basis_code":"MZ-AML-14-2023-ART-43",
    "retention_until":"2036-07-31"
  }'

The Workbench reads only posted transactions from Ledger Core. Any incomplete regulatory mapping rejects processing. A successful export reaches GENERATED and exposes a 2048-byte US-ASCII header/detail/trailer file.

Stage an inbound file

curl -X POST "$WORKBENCH_URL/api/legacy-imports" \
  -H "Authorization: Bearer $ACCESS_TOKEN" \
  -H "Idempotency-Key: import-provider-2026-07-15" \
  -H "X-Correlation-ID: import-run-2026-07-15" \
  -F "file=@regulatory-transactions.dat;type=text/plain"

Files are limited to 10 MiB and 5,000 detail records. Accepted imports reach VALIDATED; invalid files reach REJECTED with stable record, field and error codes.

State and recovery

Exports follow QUEUED -> PROCESSING -> GENERATED -> DELIVERED. Imports follow QUEUED -> PROCESSING -> VALIDATED. Validation failures use REJECTED; exhausted runtime attempts use FAILED.

  1. Retry the same request with the same idempotency key only when its payload is unchanged.
  2. Inspect the receipt and rejection report before correcting source data.
  3. Use a new idempotency key for a changed period, file or legal basis.
  4. Record authority delivery only after the generated artifact has been transmitted.

Integrity

The trailer checksum covers the header and detail records. The HTTP ETag covers the complete downloaded artifact. Retain both the receipt and authority reference as operational evidence.
